# 表格样式编辑器 · 幻灯片与 UserForm 宏版 1.0

离线单文件 PPTM，通过平台适配层支持 Linux、macOS、Windows 的文件与 UUID 接口，需要 WPS 客户端开放 JS 宏和原生 UserForm。同一文件同时提供幻灯片表单和独立 UserForm 用户窗体，无需安装加载项或网络服务。通过「打开 PPTX」编辑已关闭的其它文件，保存只写入目标文件，不自动打开或重新打开。

## 使用

1. 打开 `表格样式编辑器-幻灯片宏版-1.0.pptm` 并启用该文件的 JS 宏。在「开发工具」中退出设计模式，按 **F5** 从第一页开始放映。
2. 点击 **打开 PPTX**，先显示文件选择窗口；选择需要修改的本地 `.pptx` 后再初始化编辑器。加载期间显示“正在打开…”或“正在读取文稿…”。目标文件需先关闭。若文档控件尚未激活，在宏编辑器的 `TableStyleEditor` 模块运行一次 `OpenTableStyleEditor`，再返回第一页开始放映。
3. 选择已有自定义样式，或选择绿色、红色、蓝色、空白预设后点击 **新建**。**复制样式**为自定义样式创建独立副本。内置样式没有可编辑定义，修改时先新建。
4. 选择编辑区域，区域名称与 WPS 表格样式列表一致：整个表格、第一/第二行条纹、第一/第二列条纹、最后一列、第一列、汇总行、最后/第一个汇总单元格、标题行、最后/第一个标题单元格。然后设置填充、文字颜色、加粗、斜体及六个方向的边框。颜色下拉框提供常用色、主题色，旁边纯色块显示当前颜色；点击色块进入独立色盘页。
5. 在连续渐变区域调整饱和度和明度，下方色相条调整色相。直接点击渐变区域或按住拖动取色，松开鼠标后更新渐变；色盘不显示圆环及方块标记。输入 HEX / RGB 后按 **回车**更新预览。输入过程中不切页。原色和新色分别显示；点击 **使用颜色**才回填并返回主表单，**取消**不改原值。未提供屏幕吸管。
6. 选择所有表格、使用此样式的表格，或不更改现有表格。按需设置默认样式、清除单元格局部格式、母版默认字号，点击 **保存并应用**。
7. 保存后手动打开目标文件查看。成功不弹提示，失败显示具体错误。原文件旁保留 `.表格样式备份-时间-随机标识.pptx`。

边框颜色、线宽或线型更改会自动将该边框切换为「线条」。单独选择「继承」会移除该区域对边框的设置，继承整个表格等上层规则；继承状态没有独立线宽。线宽默认 1 磅，支持 0.25–20 磅及小数，右侧上下箭头每次增减 0.25 磅；默认字号的箭头每次增减 1 磅。也可直接输入或使用键盘上下键。

主表单采用固定布局，已移除放大、缩小、适应和比例显示，也不再建立缩放用的备用主表单页。取色及保存不改变表单控件的位置、尺寸和字号。预览只显示配色和字形，不模拟全部边框、主题及复杂效果。

## UserForm 用户窗体

切换到**第 4 页**，按 **Shift+F5** 从本页放映，再点击 **打开 UserForm 窗体**。也可以直接在宏编辑器运行 `OpenTableStyleUserForm`。窗口为文件内的 WPS 原生 UserForm，标题为「表格样式编辑器 · UserForm」，无需另行导入窗体或安装加载项。

窗体提供打开 PPTX、当前文稿、新建、复制、13 个区域、配色、字形、六方向边框、表格选项、应用范围、默认样式、默认字号、保存和关闭。填充、文字及六个方向的边框颜色统一采用**单个颜色下拉框 + 纯色块按钮**，下拉列表包含常用色、主题色和当前自定义颜色。可直接输入 HEX / 主题色，填充还支持「继承」「无填充」，文字支持「继承」。不再使用分开的颜色文本框和预设下拉框。

点击任意颜色旁的纯色块，打开独立的 **TableStyleColorForm「选择颜色」UserForm**。主编辑窗体保留在原位，取色期间暂停编辑。可拖动渐变区域与色相条、点击常用色块，或输入 HEX / RGB；原色、新色分别显示。点击「使用颜色」回填对应下拉框并更新色块，点击「取消」或窗口关闭按钮保留原色。确认或取消后继续使用同一个主窗体，保留区域、样式名称、线宽及其它未保存输入。

UserForm 取色不读取任何幻灯片形状，不启动放映、不切换 PPT 页面、不关闭或重新打开主窗体。幻灯片编辑器仍使用它自己的第 2、3 页色盘，两种色盘的控件和事件各自独立。

原生窗体用 32×24 个无间隔 Label 色块近似绘制饱和度/明度背景，色相条为 64 段；鼠标位置连续计算 HSV 与 RGB，取色精度不按这些色块分档。原色、新色和常用色色块均为原生控件，无网页、临时图片或浏览器依赖。拖动色相时立即更新新色，松开鼠标后更新渐变背景；直接输入 HEX / RGB 后按回车更新背景。渐变背景的细腻程度与网页位图渲染有差别。

线宽默认 1 磅，最小 0.25 磅，鼠标及键盘上下箭头每次增减 0.25 磅；字号箭头每次增减 1 磅。采用固定布局，不提供缩放按钮。

两种界面共用一份延迟加载的 ZIP/XML 运行库，编辑状态分别保留。关闭窗体后再次点击按钮，继续原来的编辑；重新打开 PPTX 会重新读取文件。切换界面不会同步未保存的修改；一端保存后，另一端若仍在编辑同一个旧样式，保存会提示样式已更改，需要重新打开目标文件读取最新定义。

工具文件仍需保存为 **PPTM** 才能保留 JS 宏和窗体。编辑的目标文件仍为普通 **PPTX**。

## 本版改动与验证边界

本版将幻灯片编辑器、原生 UserForm 编辑器及原生 UserForm 色盘合并到同一 PPTM。自动检查覆盖颜色字段、窗口事件、数值增减、ZIP/XML 写入与错误恢复；实际 WPS 渲染和鼠标交互需在目标客户端验证。

保留首次打开的优化：先弹出文件选择窗口，选择后才加载运行库；颜色列表延迟到聚焦时填充，初次打开复用同一次文件解析，后续检查和保存仍重新读取磁盘。主表单与色盘的原生控件引用分别缓存，避免重复解析整组控件。诊断宏记录初始化及文件载入耗时。

文件含四张预先建立的页面：第一页为固定主表单，第二、三页为相同布局的色盘，第 4 页为 UserForm 启动页。控件保持可见；需重绘渐变时先在未显示的另一张色盘页更新，再切页，不重载当前页。拖动过程中不切页。确认或取消后返回第一页。点击空白区域不会自动翻页，请通过工具栏和色块操作。

事件携带页面编号，只接受当前页面的事件；程序赋值及切页过程触发的事件、旧页的延迟事件会被忽略。切页失败时显示具体错误。返回色盘失败时仍允许重试取消。

自动检查覆盖模拟打开/保存、颜色回填、不同页面切换、固定布局与输入保留、数值增减、延迟加载、文件读取次数、原生事件过滤、失败恢复、ZIP/XML 关系、控件属性与布局。模拟宿主禁止当前页重载、修改控件显隐及取色时增删形状。

这些检查不能代替当前 WPS 的实际放映渲染和鼠标交互验证。当前版本尚未完成 WPS 实机交互验证，也未测得首次打开的实际耗时，不能保证已消除用户报告的约 5 秒等待。随包图片是设计预览。若遇到问题，可运行 `DiagnoseTableStyleEditor` 查看版本、初始化、打开耗时和最后取色事件。

## 文件与宏

共 153 个幻灯片原生控件：主表单 110 个，两张色盘页各 19 个，UserForm 启动页 5 个；另有主编辑器和选择颜色两个原生用户窗体。每张幻灯片色盘页预置两个渐变矩形，不包含圆环或位置标记；透明 Label 接收渐变区域的鼠标坐标，普通矩形通过 `Fill.UserPicture` 嵌入宏生成的 BMP，临时 BMP 随后删除。UserForm 色盘通过自己的原生 Label 绘制渐变，不使用这些形状或 BMP。控件与窗体结构依据用户保存的 `幻灯片控件样本.ppt` 和 `原生窗体样本.pptm`。

四个标准模块：`TableStyleEditor` 为简短入口，`TableStyleEvents` 为幻灯片控件事件，`TableStyleRuntime` 为共用的离线 ZIP/XML 和编辑逻辑，`TableStyleUserForm` 为两个窗体的入口及事件。`TableStyleForm`、`TableStyleColorForm` 对话框模块仅含原生窗体资源，代码放在标准模块中。渐变背景色块不生成逐个事件函数，只有覆盖渐变区域的两个透明 Label 接收鼠标事件。运行库保持多行代码，默认不打开其编辑窗口，避免巨长单行增加宏编辑器负担。

目标保存后仍是普通 PPTX，不含工具宏与控件，亦可作为 Pandoc 参考文稿：

```bash
pandoc input.md --reference-doc reference.pptx -o output.pptx
```

WPS 可能按样式 ID 缓存配色。样式定义发生更改时沿用原有编辑逻辑生成新 ID；工具不强制重启 WPS，也不自动打开目标文件。

## 构建

构建需要 Node.js、Python、Pillow 和 fontconfig。生成的 PPTM 运行时不需要这些构建工具。

```bash
npm run build:slide-macro
npm run package:slide-macro
```

文件和 UUID 统一由 `platform-services.js` 提供。文件优先使用 WPS FileSystem，缺少时才调用 Linux libc、macOS libSystem 或 Windows Unicode 文件 API。UUID 优先用 JS Crypto，没有时使用纯 JS 生成 UUID v4 格式的 ID，不使用系统 UUID 文件或 FFI。NixOS 本地构建还会读取正在运行的 WPS 已加载的 libc 路径，并保留常见路径回退。测试用 Koffi 桥接实际系统文件 API，不会打包进宏模板。

未修改已安装加载项、WPS 配置、原有独立窗体版、用户样本或参考母版。
